# Glossary

| Term | Meaning |
|------|---------|
| **Git** | Version-control software that records the history of files |
| **GitHub** | A website that hosts Git repositories and adds collaboration tools |
| **Repository (repo)** | A project folder plus its full history |
| **Commit** | A saved snapshot of changes, with a message |
| **Diff** | The line-by-line difference between two versions |
| **Branch** | A parallel line of work. `main` is the official one |
| **Pull request (PR)** | A proposal to merge a branch into `main`, with review and tests |
| **Merge** | Combine a branch's changes into another branch |
| **Clone** | Copy a repository from GitHub to your computer |
| **Push / Pull** | Send your commits to GitHub / fetch others' commits from GitHub |
| **Issue** | A to-do, bug or discussion attached to a repository |
| **Template repository** | A repository you can copy to start a new one |
| **GitHub Pages** | Free website hosting from a repository |
| **GitHub Actions** | Automation that runs on GitHub's computers, e.g. tests |
| **Workflow** | A file in `.github/workflows/` telling Actions what to do |
| **Markdown (.md)** | Plain text with simple formatting marks, turned into web pages |
| **Jekyll** | The tool GitHub Pages uses to turn Markdown into a website |
| **CSS** | The language that controls a web page's colours, fonts and layout |
| **YAML (.yml)** | A simple settings-file format of `key: value` lines. Indentation matters |
| **`.gitignore`** | A list of files Git should never track (e.g. data, results) |
| **Test** | Code that checks other code gives the right answer |
| **CLAUDE.md** | A file of instructions Claude reads before working in a repository |
| **Release / tag** | A named version (e.g. `v1.0.0`), such as the one used in a paper |
